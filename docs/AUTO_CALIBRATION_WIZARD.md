# 自动标定向导（测试性）

新建 CD/DVD 工程时可选择自动标定向导。标记盘生成、验证和测量由主仓库中的 C# 自动标定核心完成，不依赖 Discratcher 子模块或 Rust 工具。测量完成后可将几何参数应用到工程，并生成粗标定、边界标定和精细标定三份辅助标定记录。Discratcher 预设 JSON 仍可导入。

## 来源、范围与结果边界

本向导源自 [Discratcher](https://github.com/POPCORNBOOM/Discratcher)，是面向 DiscImageStudio 的 C# 移植和集成实现；它不启动或调用 Discratcher 本体，也不需要其 Rust 工具链。感谢 POPCORNBOOM 开发并开源 Discratcher。

移植实现借鉴了原项目的自动标定流程，但光驱适配、计时、采样、参数拟合和应用集成由本项目的 C# 代码负责。因此，本实现的测量效果和结果不代表 Discratcher 本体，也不保证与其输出一致。文中提到的兼容仅指明确说明的预设格式、选项范围或特定设备命令策略，不代表两个完整测量引擎等价。

## 工作流程与模块职责

1. **获取介质信息。** 准备页查询光驱、介质类型、空白状态和容量。默认用空白盘容量确定标记镜像长度；高级选项允许把光驱报告的数据逐项手动填写。此时不会读取空白盘的数据扇区。
2. **准备并刻录标记盘。** C# 核心生成带有可识别卷标和采样布局的 CD/DVD 镜像。用户可以由向导流式刻录，也可以导出镜像后使用外部软件刻录。读取页会检查标记盘身份、镜像长度和采样扇区，而不是仅凭设备列表中可能不准确的空白状态判断。
3. **读取和拟合。** 用户选择读取光驱并插入标记盘。测量核心按设定的阶梯采样位置执行计时读取，再根据相位/时间样本拟合盘片几何；不稳定或不符合规格的结果会标记为可疑，不应在未经核对时应用。
4. **应用与导出。** 完成按钮才会把确认后的几何应用到新工程。另可导出三份 `.calibration.json` 辅助标定记录（粗标定、边界标定、精细标定）；记录保留测得的几何，但图片和像素观察为空白，后续可在辅助标定页面继续编辑。

主要代码分层如下：

- `DiscImageStudio.AutoCalibration`：标记镜像构造、测量阶梯、几何拟合、结果验证、预设导入和辅助标定记录转换。
- `DiscImageStudio.AutoCalibration.Drives`：Windows SPTI、Linux SG_IO 和 macOS 只读回退实现。其传输能力和介质元数据能力因平台而异。
- `AutoCalibrationService`：连接向导与 C# 核心及光驱适配器。
- `AutoCalibrationWizardWindow`：新建工程后的分步界面，负责设备选择、手动介质参数、刻录/导出、测量、进度与最终应用确认。
- 设置中的自动向导调试模式：以模拟驱动器走完整流程，不访问实体光驱；模拟结果只用于检查 UI 和流程，不是硬件测量结果。

## 空白盘与镜像

“重读光盘参数”通过 C# 光驱后端读取介质类型、空白状态和容量。生成标记镜像不读取空白盘的数据扇区；这些元数据仅用于确定介质和镜像大小。

外部镜像导出必须先读取到与当前工程类型匹配的空白盘参数，或明确启用手动参数模式：

- 介质类型和总扇区数会分别显示在输入框中；未启用手动模式时为只读，勾选后可编辑。手动类型只接受 CD-R/CD-RW/DVD-R/DVD+R/DVD-RW/DVD+RW，并须与当前工程类型一致。
- CD 镜像大小为 `min(总扇区数, 359849) - 64`，且至少保留 50000 个镜像扇区。
- DVD 使用标准单层 DVD 镜像大小 2295104 扇区；输入容量必须足以容纳该镜像。
- 流式刻录仍由 IMAPI2 检查实际介质是否为空白及是否有足够容量；手动参数不会绕过这项检查。

测量高级选项采用与 Discratcher 一致的可选范围：目标点数 16–72（步进 4）、每点重复数 16–60（步进 4）、下限 1–10%、上限 80–98%。问号提示说明了各参数含义和耗时影响。Windows/Linux 后端对计时 READ(12) 使用 FUA，沿用 Discratcher 的这一设备命令策略，以避免每个采样前额外读取远端扇区；设备拒绝 FUA 时会报告错误，而不会静默切换成采样行为不同的路径。该策略上的一致不代表测量结果等同。

相同标记盘并不保证两次测量得到完全相同的浮点参数：读取完成时间受光驱寻道、转速波动和重试影响。相同设备、介质类型和高级选项下，几何应落在相近范围；若半径、总扇区数或螺距出现明显偏差，应检查读速/FUA错误、测量是否 suspect，以及设备是否在两次运行中改变了缓存或速度状态。

准备页的信息窗口会显示每次光驱查询的结果。读取标记盘时，程序不会用设备列表中的空白状态或面向写入的支持标志预先拒绝介质（刻录后的 DVD-R 也可能报告为 DVD-ROM），而是校验卷标、镜像长度和采样扇区，并显示具体错误。

## 导入 Discratcher 参数

欢迎页可导入 Discratcher 保存的 `presets.json`、单个导出预设，或包含 `preset` 字段的 `calibrations.json`。Windows 默认数据目录通常为 `%APPDATA%\dev.popcornboom.discratcher\`。

导入列表只显示与当前 CD/DVD 工程类型相同的预设。内外半径、总扇区数、螺距和残差会映射到 DiscImageStudio；DiscImageStudio 没有与 Discratcher 的 CD 通道位长或 `alongTrackFrames` 对应的完全等价字段，界面会注明未映射的值，不会静默覆盖其他参数。采用导入的预设会跳过插盘和测量步骤，但仍需显式点击“完成，应用到工程”。

## 调试

在设置中启用自动向导调试选项，可用内置模拟光驱预览完整的测量流程。调试模式不会访问真实光驱，也不会生成或刻录大型镜像。

算法核心可在 Windows、macOS 和 Linux 上复用；当前 WPF 应用和向导界面仍仅支持 Windows。macOS 当前使用只读原始设备回退，不支持 SCSI 透传、准确介质状态、FUA 或 raw CD sector 读取；该平台仍可能比 Windows/Linux 慢，且 macOS 硬件测量尚未验证。

## 项目加载故障排查

自动标定核心和光驱适配器项目均登记在 `DiscImageStudio.slnx` 中。若在切换分支或更新工作区时 IDE 短暂报告这两个 `.csproj` 文件不存在，先确认版本控制操作已完成，再重新加载解决方案；随后用 `dotnet sln DiscImageStudio.slnx list` 检查项目清单并运行解决方案构建。若重载后仍失败，检查工作区是否缺少这两个项目目录或包含未完成的冲突，而不要只从旧的项目系统日志判断文件状态。
